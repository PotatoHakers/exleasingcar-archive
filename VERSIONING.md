# Версии проекта

Проект пока находится на ранней стадии разработки. Для заметных контрольных точек используем версии в формате `vMAJOR.MINOR.PATCH` и Git-теги. Не нужно выпускать новую версию для каждого Issue или pull request.

- **PATCH** (`v0.1.1`) — исправления ошибок и небольшие изменения без нового заметного поведения.
- **MINOR** (`v0.2.0`) — полезная новая функциональность, совместимая с существующим использованием проекта.
- **MAJOR** (`v1.0.0`, затем `v2.0.0` и т. д.) — несовместимые изменения, которые требуют менять привычный способ использования проекта.

Git-тег указывает на конкретный commit. На его основе в GitHub можно опубликовать Release с кратким описанием изменений. Теги и Releases создаём для полезных этапов проекта, а не автоматически после каждого слияния.

Версия проекта не связана с `SCHEMA_VERSION`: она описывает выпуск приложения, а `SCHEMA_VERSION` — версию схемы SQLite и меняется только при изменениях схемы базы данных.
