`Локальный архив публичных данных Exleasingcar.`

## GITHUB

### BRANCHES

- `git branch` - список локальных веток
- `git branch -r` - список веток в удаленном репозитории
- `git branch -a` - список всех локальных и удаленных веток
- `git branch -vv` - посмотреть ветки и их связь
    (Показывает:
    - Название ветки.
    - Последний коммит.
    - Связанную удаленную ветку.
    - Статус относительно удаленной ветки.)
- `git branch -d feature/my-feature` - удалить локальную ветку
    (Удаляет ветку, если она уже объединена с другой веткой.)
- `git push origin --delete feature/my-feature` - удалить удаленную ветку с GitHub

### STATUS & DIFF

- `git status` - сравнение текущих файлов с последним коммитом в текущей ветке
    (Показывает:
    - Текущую ветку.
    - Измененные файлы.
    - Новые файлы.
    - Файлы, добавленные через git add.)
- `git diff` - посмотреть разницу в коде
    (Показывает изменения, которые еще не добавлены через git add.)
- `git diff --cached` - посмотреть подготовленные изменения
    (Показывает изменения, которые уже добавлены через git add и попадут в следующий commit.)
- `git log --oneline -5` - посмотреть последние 5 коммитов
- `git log origin/master..HEAD --oneline` - посмотреть коммиты текущей ветки, которых нет в удаленном master
- `git diff origin/master...HEAD` - посмотреть изменения текущей ветки относительно общей точки, от которой она разошлась с origin/master

### REMOTE & SYNC

- `git remote -v` - посмотреть адреса удаленных репозиториев
    (Показывает:
    - Название удаленного репозитория.
    - URL для получения изменений.
    - URL для отправки изменений.)

- `git fetch origin` - обновляет локальную информацию о состоянии удаленного репозитория origin
    (fetch получает изменения и обновляет локальные ссылки на удаленные ветки согласно настройкам репозитория.
    При этом:
    - Текущая ветка не переключается.
    - Твои рабочие файлы не изменяются.
    - Локальные коммиты не объединяются с удаленными.
    - Загружаются необходимые Git-объекты и коммиты.)

- `git pull` - получает новые изменения из удаленной ветки, связанной с текущей локальной веткой, и применяет их к ней
- `git pull origin master` - получает изменения именно из удаленного master и применяет их к текущей ветке
    (Важно:
    - Команда не переключает тебя на master.
    - Изменения origin/master применяются к текущей ветке.
    - Может произойти merge или fast-forward в зависимости от ситуации и настроек Git.)

- `git config --get-all remote.origin.fetch` - проверить настройку fetch
    (Показывает, какие удаленные ветки Git получает при выполнении git fetch origin.
    Стандартная настройка:
    `+refs/heads/*:refs/remotes/origin/*`
    Означает, что Git получает информацию обо всех ветках origin.)

### CREATE & SWITCH BRANCH

- `git switch master` - переключиться на локальную ветку master
- `git switch feature/my-feature` - переключиться на существующую локальную ветку
- `git switch -c feature/my-feature` - создать новую ветку от текущей ветки и сразу переключиться на нее
- `git switch -c feature/my-feature master` - создать новую ветку от конкретной локальной ветки master и сразу переключиться на нее
- `git fetch origin` + `git switch -c feature/my-feature origin/master` - создать новую ветку от актуального удаленного master
    (1. `git fetch origin` - обновляет локальную информацию об удаленном репозитории.
    2. `git switch -c` - создает новую локальную ветку.
    3. `origin/master` - указывает, от какого коммита создавать новую ветку.
    4. Git автоматически переключает тебя на новую ветку.
    5. Переключаться отдельно на master не нужно.)

### COMMIT & PUSH

- `git add .` - добавить изменения в текущей директории и ее вложенных папках
- `git add -A` - добавить все изменения проекта
    (Добавляет:
    - Новые файлы.
    - Измененные файлы.
    - Удаленные файлы.)
- `git commit -m "feat: add new functionality"` - создать коммит
    (Сохраняет подготовленные через git add изменения в истории текущей ветки.)
- `git push -u origin feature/my-feature` - опубликовать новую локальную ветку на GitHub
    (Делает следующее:
    - Отправляет коммиты на GitHub.
    - Создает удаленную ветку, если ее еще нет.
    - Связывает локальную ветку с удаленной.)
- `git push` - отправить новые коммиты в уже связанную удаленную ветку

### PULL REQUEST & MERGE
- `git merge feature/my-feature` - объединить указанную локальную ветку с текущей локальной веткой
    (Важно:
    - Перед выполнением нужно находиться в целевой ветке.
    - Например, если ты находишься в master, команда объединит feature/my-feature в master.
    - При использовании GitHub PR выполнять эту команду локально необязательно.)

## STASH

`Stash` - временное локальное хранилище Git для незакоммиченных изменений.

### SAVE

- `git stash` - временно сохранить отслеживаемые изменения
- `git stash push -m "message"` - сохранить изменения с описанием
- `git stash push -u -m "message"` - сохранить изменения и новые файлы
    (Сохраняет:
    - Измененные отслеживаемые файлы.
    - Изменения, добавленные через git add.
    - Новые файлы, которые еще не отслеживаются Git.

    При этом:
    - Изменения убираются из рабочей директории.
    - Commit не создается.
    - Изменения не отправляются на GitHub.
    - Stash остается локально внутри Git-репозитория.)

- `git stash push -a -m "message"` - сохранить изменения, включая игнорируемые файлы
    (Параметр -a дополнительно включает файлы, указанные в .gitignore.)

### VIEW & CHECK

- `git stash list` - посмотреть все сохранения
    (Показывает:
    - Номер сохранения: stash@{0}, stash@{1} и т.д.
    - Название сохранения.
    - Ветку и коммит, на основе которых оно было создано.)

- `git stash show stash@{0}` - посмотреть список файлов в конкретном сохранении
- `git stash show -p` - посмотреть сохраненный код
- `git stash show -p 'stash@{0}'` - посмотреть полный список изменений конкретного сохранения

### APPLY & RESTORE

- `git stash apply` - вернуть последние сохраненные изменения, сохранив Stash
    (При этом:
    - Изменения возвращаются в рабочую директорию.
    - Сохранение остается в Stash.
    - Его можно применить повторно.)

- `git stash apply 'stash@{0}'` - вернуть конкретное сохранение, не удаляя его из Stash

- `git stash pop` - вернуть последние сохраненные изменения и удалить Stash при успешном применении
    (При этом:
    - Изменения возвращаются в рабочую директорию.
    - Если восстановление прошло успешно, запись удаляется из Stash.
    - Если возник конфликт, Stash остается в хранилище.)

- `git stash pop 'stash@{0}'` - вернуть конкретное сохранение и удалить его после успешного применения

- `git stash branch feature/my-feature 'stash@{0}'` - создать новую ветку и перенести в нее сохраненные изменения
    (Делает следующее:
    1. Создает ветку от коммита, на котором был создан Stash.
    2. Переключается на новую ветку.
    3. Применяет сохраненные изменения.
    4. Удаляет Stash при успешном применении.)

### DELETE

- `git stash drop` - удалить последнее сохранение
- `git stash drop 'stash@{0}'` - удалить конкретное сохранение
- `git stash clear` - удалить все сохранения из Stash
    (Важно:
    - Операция удаляет все записи Stash.
    - Не используй ее, если в Stash есть нужные изменения.)

### PRACTICAL EXAMPLES

- Сохранить изменения перед pull:
    ```bash
    git stash push -u -m "before pull"
    git pull
    git stash pop
    ```

- Перенести изменения в другую ветку:
    ```bash
    git stash push -u -m "move changes"
    git switch feature/my-feature
    git stash pop
    ```

- Посмотреть сохранения и вернуть конкретное:
    ```bash
    git stash list
    git stash apply 'stash@{0}'
    ```

- Разрешить конфликт после stash pop:
    (1. Открыть конфликтный файл.
    2. Вручную объединить нужные изменения.
    3. Удалить маркеры конфликта.
    4. Выполнить git add для разрешенного файла.
    5. Проверить результат через git status.
    6. Если Stash остался, удалить его через git stash drop только после проверки, что изменения восстановлены.)

## WORKTREE

`Worktree` - отдельная рабочая папка Git, которая использует общую Git-базу основного репозитория.

(Каждый Worktree имеет:
- Собственные файлы проекта.
- Собственную рабочую директорию.
- Собственное состояние изменений.
- Отдельную текущую ветку или коммит.

При этом:
- Все Worktrees используют общую историю коммитов.
- Все Worktrees используют общую Git-базу.
- Изменения файлов в одной папке не появляются автоматически в другой.
- Одну локальную ветку нельзя одновременно открыть в двух Worktrees.)

### VIEW & CHECK

- `git worktree list` - посмотреть все рабочие папки
    (Показывает:
    - Путь к каждой папке.
    - Текущий коммит.
    - Используемую ветку.
    - Detached HEAD, если папка открыта на конкретном коммите.)

- `git -C "Путь" status` - проверить состояние конкретной рабочей папки
    (Параметр -C позволяет выполнить команду Git в указанной папке, не переходя туда через cd.)

### CREATE WORKTREE

- `git worktree add -b feature/my-feature "C:/Users/mix123/projects/my-feature" origin/master` - создать отдельную рабочую папку и новую локальную ветку от origin/master
    (Параметры:
    - `git worktree add` - создать новую рабочую папку.
    - `-b` - создать новую локальную ветку.
    - `feature/my-feature` - название новой ветки.
    - Путь - место создания рабочей папки.
    - `origin/master` - коммит, от которого создается новая ветка.

    После выполнения:
    - Создается новая папка.
    - В ней появляется копия файлов проекта.
    - Создается новая локальная ветка.
    - Git автоматически подключает ветку к новой папке.
    - Переключаться через git switch не нужно.)

- `git worktree add "C:/Users/mix123/projects/my-feature" feature/my-feature` - создать рабочую папку для уже существующей локальной ветки
    (Ветка не должна быть открыта в другом Worktree.)

- `git worktree add --detach "C:/Users/mix123/projects/test-commit" abc123` - создать рабочую папку для конкретного коммита
    (Detached HEAD - режим, в котором Worktree привязан к конкретному коммиту, а не к ветке.
    Удобно для:
    - Проверки старой версии приложения.
    - Тестирования конкретного коммита.
    - Проверки изменений из PR.)

### REMOVE WORKTREE

- `git worktree remove "C:/Users/mix123/projects/my-feature"` - удалить рабочую папку
    (Удаляет:
    - Файлы рабочей папки.
    - Регистрацию Worktree в Git.

    При этом:
    - Сама локальная ветка не удаляется.
    - Общая Git-история не удаляется.
    - Git не позволит удалить Worktree с незакоммиченными изменениями без дополнительного подтверждения через force.)

- `git worktree prune` - удалить устаревшие записи о Worktrees, которых больше нет на диске
    (Используется, если рабочая папка была удалена вручную через Проводник Windows.)

## USEFUL COMMANDS

- `git remote -v` - проверить адрес удаленного репозитория
- `git rev-parse --show-toplevel` - посмотреть корневую папку Git-репозитория
- `git rev-parse --abbrev-ref HEAD` - посмотреть название текущей ветки
- `git show HEAD` - посмотреть информацию о последнем коммите
- `git diff --stat` - посмотреть краткую статистику изменений
- `git reflog` - посмотреть историю перемещений HEAD и переключений между коммитами
- `git clean -nd` - посмотреть, какие неотслеживаемые файлы будут удалены командой git clean
    (Команда ничего не удаляет, а только показывает список.)
